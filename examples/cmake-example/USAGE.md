# How to Run This Example

This example demonstrates using Qompoter with CMake to manage C++ dependencies.

## Prerequisites

- Qompoter installed
- CMake 3.10 or later
- A C++ compiler (g++, clang, etc.)

## Steps

### 1. Set up a local Qompoter repository

First, create a local repository with the example library:

```bash
# From the cmake-example directory
mkdir -p local-repo/example/my-library/v1.0.0
cp -r my-library/* local-repo/example/my-library/v1.0.0/
```

### 2. Install dependencies using Qompoter

Navigate to the project directory and run Qompoter to fetch dependencies:

```bash
cd my-project
qompoter update --repo ../local-repo
```

This will:
- Download `my-library` into the `vendor/` directory
- Generate `vendor/vendor.cmake` with the package paths
- Create `qompoter.lock` to lock dependency versions

You should see output like:
```
Qompoter
======== update

* example/my-library v1.0.0
  Downloading sources...
  done

done
```

### 3. Verify the generated vendor.cmake

Check that `vendor/vendor.cmake` was created:

```bash
cat vendor/vendor.cmake
```

You should see something like:
```cmake
# This file is auto-generated by Qompoter
# It sets up CMAKE_PREFIX_PATH to include all vendor packages with cmake/ directories

get_filename_component(QOMPOTER_VENDOR_DIR "${CMAKE_CURRENT_LIST_DIR}" ABSOLUTE)

## Start example/my-library ##
list(APPEND CMAKE_PREFIX_PATH "${QOMPOTER_VENDOR_DIR}/my-library")
## End example/my-library ##
```

### 4. Build the project with CMake

```bash
mkdir build
cd build
cmake ..
make
```

### 5. Run the application

```bash
./my-app
```

Expected output:
```
Hello from MyLibrary!
Library version: 1.0.0
```

## What Just Happened?

1. **Qompoter** downloaded the dependency and placed it in `vendor/my-library/`
2. **vendor.cmake** added `vendor/my-library` to `CMAKE_PREFIX_PATH`
3. **CMake's find_package()** found `MyLibraryConfig.cmake` in `vendor/my-library/cmake/`
4. **CMakeLists.txt** linked the executable against the library target
5. The application was compiled with access to the library's headers and code

## Refreshing vendor.cmake

If you manually modify the vendor directory, regenerate `vendor.cmake` without re-downloading:

```bash
qompoter refresh-vendor-cmake
```

## Troubleshooting

**CMake can't find the package:**
- Verify `vendor/vendor.cmake` exists and includes your package
- Check that `vendor/my-library/cmake/MyLibraryConfig.cmake` exists
- Ensure you're including `vendor/vendor.cmake` before calling `find_package()`

**Build errors:**
- Make sure the library's `*Config.cmake` file correctly specifies include directories
- Verify the library's headers are in the expected location

## Adapting This Example

To use this pattern in your own projects:

1. Create a `cmake/` directory in your library with a `<Name>Config.cmake` file
2. Add your library to `qompoter.json` in your project
3. Run `qompoter update` to fetch dependencies
4. Include `vendor/vendor.cmake` in your `CMakeLists.txt`
5. Use `find_package()` and `target_link_libraries()` as shown
